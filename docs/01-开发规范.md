# 开发规范（Development Specification）

Version：V1.0

---

# 一、开发目标

本项目遵循以下原则：

* 简单
* 稳定
* 易维护
* 易扩展
* SEO 优先
* 性能优先

所有开发必须遵守本规范。

---

# 二、开发原则

### 1、功能优先

先保证功能完整，再优化界面。

禁止为了炫酷效果增加复杂代码。

---

### 2、SEO 优先

所有页面必须符合 Google SEO 最佳实践。

任何功能不得影响搜索引擎收录。

---

### 3、保持简单

优先采用成熟方案。

不使用复杂框架。

避免过度设计。

---

### 4、统一风格

整个网站保持统一设计。

颜色、字体、按钮、间距、图标必须一致。

---

### 5、模块化开发

每一个功能都是独立模块。

新增功能不得影响已有功能。

禁止出现大量重复代码。

---

# 三、代码规范

所有代码必须：

* 注释清晰
* 命名统一
* 可读性高
* 不允许硬编码
* 配置统一放入配置文件

---

# 四、文件命名规范

统一使用小写字母。

多个单词使用下划线。

例如：

```
amazon_fee.py
shipping_calculator.py
policy_search.py
```

禁止：

```
AmazonFee.py
AmazonFeeCalculator.py
Test.py
```

---

# 五、变量命名

统一采用英文。

使用有意义名称。

例如：

```
product_price
shipping_cost
vat_rate
profit_margin
```

禁止：

```
a
b
temp
abc
```

---

# 六、函数规范

一个函数只完成一个功能。

函数长度建议不超过 50 行。

复杂逻辑必须拆分。

---

# 七、页面开发规范

所有页面必须包含：

* Title
* Meta Description
* Canonical
* H1
* Breadcrumb（需要时）
* Footer
* 内链

所有页面必须支持移动端。

---

# 八、UI规范

统一：

* Header
* Footer
* 按钮样式
* 表单样式
* 卡片样式
* 图标风格
* 字体大小
* 页面宽度

不得每个页面使用不同设计。

---

# 九、性能规范

首页加载时间目标：

≤2 秒

Google PageSpeed：

≥90 分

图片全部压缩。

CSS、JS 最小化。

禁止加载无用资源。

---

# 十、安全规范

所有用户输入必须进行验证。

禁止直接拼接 SQL。

API Key 不得写入代码。

所有敏感配置统一使用 `.env`。

错误信息不得暴露服务器信息。

---

# 十一、开发规范

开发流程统一如下：

产品设计

↓

页面设计

↓

功能开发

↓

本地测试

↓

SEO 检查

↓

部署测试

↓

上线

未经测试不得上线。

---

# 十二、Cursor 开发规范

Cursor 每次仅完成一个功能模块。

禁止一次修改多个模块。

修改前必须阅读相关开发文档。

不得擅自修改项目结构。

不得删除已有功能。

所有新增代码必须与现有代码风格保持一致。

---

# 十三、最终目标

整个项目保持：

* 结构统一
* 命名统一
* UI统一
* SEO统一
* 易维护
* 易扩展

任何新增功能都应在不影响已有功能的前提下完成。
