# 07-开发实施规范.md

# Development Implementation Specification

Version：V1.0

---

# 一、开发目标

按照前面 00~05 文档，开发一个可直接上线的 MVP。

要求：

* 可部署
* 可维护
* 可扩展
* SEO 友好
* 响应速度快
* 支持后续增加 100+ 工具

开发过程中不得偏离前面所有文档。

---

# 三、开发顺序

严格按以下顺序开发：

1. 首页
2. 工具分类页
3. 单工具模板
4. Amazon Fee Calculator
5. FBA Profit Calculator
6. VAT Calculator
7. Shipping Calculator
8. Negative Review Reply Generator
9. Product Description Generator
10. About / Contact / Privacy / Terms
11. SEO
12. 上线

不得跳步骤。

* Category Card
* Search Box

# 六、Calculator 规范

所有 Calculator：

输入参数

↓

本地计算

↓

返回结果

↓

AI分析（可选）

简单计算不得调用 AI。

优先本地计算。

# 七、数据库规范

第一版：

MySQL 8

ORM：
SQLAlchemy

数据库迁移：
Alembic。

存储：

* 工具配置
* FAQ
* 分类
* Blog（预留）

业务逻辑与数据库分离。


---

# 八、SEO 规范

所有页面必须自动生成：

* Title
* Meta Description
* Canonical
* Open Graph
* Twitter Card
* Sitemap
* robots.txt
* Schema
* FAQ Schema
* Breadcrumb Schema

每个工具拥有唯一 URL。

---

# 九、安全规范

* API Key 使用 `.env`
* 所有输入进行校验
* 表单过滤非法字符
* 错误信息不暴露系统细节
* 防止重复提交

---

# 十、测试规范

每开发完成一个模块，必须检查：

* 页面正常访问
* 响应式正常
* SEO 标签完整
* 无控制台报错
* 无 404、500
* Lighthouse ≥90（Performance、SEO）

不合格不得进入下一模块。

---

# 十一、上线规范

上线前必须完成：

* Docker 构建成功
* Nginx 配置完成
* HTTPS 正常
* robots.txt
* sitemap.xml
* favicon
* 404 页面
* Google Search Console 提交
* Google Analytics 接入（预留）
* AdSense 代码预留（暂不启用）

---

# 十二、Cursor 开发要求

Cursor 必须遵守：

1. 严格按照 docs 文档开发。
2. 不得修改项目结构。
3. 不得修改 UI 风格。
4. 不得自行新增框架。
5. 所有代码必须模块化。
6. 所有页面必须响应式。
7. 所有工具必须复用统一模板。
8. 完成一个模块后自行运行测试，确保无错误后再结束。

---

# 十三、开发环境规范

本地开发默认采用：

FastAPI + Laragon + MySQL 8 直接运行和调试。

开发过程中不使用 Docker 进行日常调试。

仅在以下情况使用 Docker：

* Sprint 完成验收
* Release 发布
* 部署生产服务器

---

# 十四、MVP 完成标准

达到以下条件即可上线：

* 首页完成
* 工具分类完成
* 6 个核心工具完成
* About / Contact / Privacy / Terms 完成
* SEO 基础完成
* Docker 部署完成
* HTTPS 正常
* Google 可收录

满足以上条件即发布 V1.0，后续以新增工具和内容为主要迭代方向，不再进行大规模架构调整。
